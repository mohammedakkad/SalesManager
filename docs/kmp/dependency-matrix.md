## How the status was decided (evidence rule)

Every status below comes from the **Gradle module metadata** (`.module` file) of that exact version, read from Google Maven or Maven Central. Where an artifact has no `.module`
the POM packaging is used (`jar` or `aar`); those rows are marked `pom`. Nothing was decided from memory.

- **KMP-ready**: the root module has `common` metadata plus a real Android variant and a real desktop JVM variant (or a `jvm` variant that serves both).
- **JVM-only**: plain JAR, no KMP metadata. Usable from `jvmShared` (Android + desktop).
- **Android-only**: AAR, or a KMP artifact that publishes only Android plus a **stub** JVM variant. Variant names containing `stubs` (`jvmStubs`, `jvmstubs` artifact) are treated as not usable on desktop. This is how androidx publishes Compose, Navigation and some Lifecycle artifacts.
- **Build-time**: Gradle plugins and annotation processors. **Platform (BOM)**: BOM only.
- Newer versions: "newer X" gives the `minCompileSdk` read from the `aar-metadata.properties` inside the Android AAR, and the Kotlin version recorded in the artifact's `kotlin-tooling-metadata.json` (the Kotlin the library was built with). No `minAgpVersion` was present in any inspected AAR metadata. Anything that could not be read says "not verified".
- Evidence links point to the canonical repositories (`dl.google.com/android/maven2`, `repo1.maven.org`). The files were fetched from a Maven Central mirror because the build container is throttled by Maven Central (see `baseline.md`, Risks); the content is identical.
- "Used by" comes from the module `build.gradle.kts` files plus a count of files that import the library in `src/main` (grep). Libraries pulled with `api(...)` by `:app` are visible to `:salesmanager` and `:admin`.

## Newer versions and compileSdk 37

Several newer versions of the pinned libraries require `compileSdk 37` (AAR metadata `minCompileSdk`):
`androidx.compose.*` 1.13.0, `material3` 1.5.0, `navigation-compose` 2.10.2, `lifecycle-viewmodel-compose` 2.11.1, `core-ktx` 1.19.1, `coil` 3.6.3, `okhttp` 5.5.1, Vico 3.3.1. The project is on compileSdk 36, so these are **blocked until the compileSdk 37 owner decision** (already open in PR #52).
The Kotlin versions recorded in their tooling metadata (2.2.x to 2.4.20) are not newer than the project's Kotlin 2.4.21. Compatibility of Compose Multiplatform 1.12.2 and the JetBrains forks with Kotlin 2.4.21 and AGP 9.5.2 is **not verified**: the `compose-gradle-plugin` metadata declares no Kotlin or AGP minimum, and the release notes were not read. K0.4 (spike) must confirm it.

## Blockers and decisions

Feeding **K1.3 (desktop Firebase)**
1. Every Firebase Android artifact (database, firestore, auth, messaging, crashlytics, analytics, config) is Android-only (AAR). The BOM has no JVM variant.
2. Option (a) `dev.gitlive:firebase-*` 2.8.0 has a published `jvm` variant on a JVM port of the SDK: parity with the Android SDK (listeners, offline cache, security-rules behaviour) is not verified.
3. Option (b) REST needs an HTTP client: OkHttp 5.4.0 (already used, KMP-ready) or Ktor 3.6.1 (KMP).
4. New finding: `com.google.firebase.auth` is imported only in `:admin`. Neither `:app` nor `:salesmanager` imports it, so seller activation may not need Firebase Auth. Confirm in the K1.3 spike, because it changes the auth part of the decision.

Feeding **K5.5 (charts)**
5. Vico 1.15.0 (pinned) is Android-only (AAR). Vico 3.x is KMP (first 3.0.0) but 3.3.1 needs compileSdk 37 and a different API, so a Canvas chart or a Vico 3 migration after the compileSdk decision are the two options.

Feeding **K6.1 (PDF)**
6. `android.graphics.pdf` is a platform API (no artifact). PDFBox 3.0.8 is JVM-only and already used by `qa/pdf-verifier`; Arabic shaping is unverified. Skiko 0.156.1 is KMP; PDF capability unverified.

New findings
7. **androidx Compose, Navigation and `lifecycle-viewmodel-compose` 2.10.0 are Android + jvmstubs.** The seller UI cannot compile for desktop with them: the move to `org.jetbrains.compose.*` and `org.jetbrains.androidx.*` is part of K1.1 and K5. This is why `commonMain` in `:shared:seller-ui` needs Compose Multiplatform versions, not the BOM.
8. **WorkManager** (`work-runtime-ktx`, imported in 7 files across the modules) and `koin-androidx-workmanager`: Android-only, replaced on desktop by the K4.5 scheduler.
9. **CameraX and ML Kit**: 1 file (`BarcodeScannerScreen`); Android-only. Desktop uses the keyboard-wedge scanner behind an interface.
10. **Crashlytics and FCM**: Android-only; desktop uses a local log file and realtime listeners.
11. `org.json` is imported in `CloudinaryUploader.kt` (Android platform class, no desktop artifact), and `AppDatabase` imports `androidx.sqlite.db.SupportSQLiteDatabase`. Both need a replacement or a `jvmShared` library in K3.
12. `gson` is used in 4 `:salesmanager` files. It is JVM-only, so it can live in `jvmShared` but not in `commonMain` (rule 4); `kotlinx-serialization-json` 1.13.0 is the KMP alternative.
13. Declared but unused (no source import): `firebase-analytics`, `firebase-config`, `compose-ui-graphics`, `compose-ui-tooling-preview`. Removing them is a cleanup that **needs owner approval**.
14. `kotlinx-coroutines-swing` (JVM, 1.11.0) is the usual provider of `Dispatchers.Main` on desktop; it is not in the catalog today. Confirm in K1.4.
15. `room-ktx` (AAR) and `lifecycle-runtime-ktx` (Android-only variant) have KMP counterparts in `room-runtime` and `androidx.lifecycle:lifecycle-runtime`; whether they can simply be dropped is not verified (K3.1, K5.1).
